01

Design Principles

Tiga aturan ini mengalahkan preferensi estetika kapan pun keduanya bentrok.

1

Foto adalah UI utama — chrome harus diam

Produk ini portofolio foto, bukan aplikasi produktivitas. Setiap elemen non-foto (nav, tombol, label) harus punya kontras visual rendah terhadap foto di sekitarnya. Warna aksen (amber) hanya boleh dipakai pada area kecil & state aktif/CTA — tidak pernah sebagai fill besar berdampingan dengan foto. Kalau ragu antara “elemen UI ini menarik perhatian atau tidak”, jawabannya harus tidak.

2

Satu foto, satu konteks, satu klik

Setiap foto yang muncul di grid manapun (Home, Series, Location) wajib berjarak maksimal satu klik dari: (a) versi resolusi penuh (lightbox), dan (b) konteks tempatnya (seri atau lokasi asal). Foto tidak boleh tampil “telanjang” tanpa jalan ke ceritanya — ini konsekuensi langsung dari tujuan PRD soal penemuan berbasis cerita, bukan cuma grid Instagram kedua.

3

Tidak ada state yang diam-diam gagal

Situs ini statis, tanpa backend untuk mencatat error. Satu-satunya sinyal kegagalan yang tersedia adalah apa yang terlihat di layar pengunjung saat itu juga — maka setiap degradasi (peta gagal muat, foto gagal load, klik kontak) wajib punya representasi visual eksplisit dan actionable. “Diam saja” bukan state yang valid.

02

Arah Visual

Mood: kamar gelap yang tenang untuk melihat kontak sheet — bukan galeri putih steril.

Palet gelap + aksen amber pada MVP yang sudah live dipertahankan secara sengaja, bukan default. Amber di sini bukan pilihan estetik generik — warna itu literal muncul di sebagian besar foto JustLeps sendiri (golden hour di Prambanan, lampu jalan di foto street). Mempertahankannya berarti UI meminjam warna dari konten, bukan menimpanya.

Referensi 01

Kontak sheet analog

Nomor bingkai, coretan grease-pencil merah menyeleksi cuadro terbaik → jadi dasar badge angka pada Series & count di peta Discover.

Referensi 02

Editorial travel print

Ruang negatif besar, tipografi judul yang berani, foto full-bleed — bukan grid rapat ala dashboard.

Referensi 03

Sera Photography (live)

Struktur split-layout, hero notch, kartu rounded — dipertahankan karena sudah live & disetujui, jadi fondasi bukan titik awal ulang.

Dihindari
  • Gradient ungu–biru generik pada hero
  • Emoji sebagai penanda section atau ikon fungsional
  • Satu radius & satu shadow ditempel di semua elemen tanpa hierarki
  • Stat tile ala dashboard analitik — produk ini bukan tool data
  • Aksen neon/sangat jenuh yang bersaing kontras dengan foto itu sendiri

05

User Flow

Flow A — Klien potensial menghubungi (Persona: Dinda)

  1. Membuka tautan situs dari bio Instagram/story teman → mendarat di Home, carousel hero langsung menampilkan 5 foto unggulan.
  2. Scroll ke Latest Travel/Series, klik satu seri yang relevan dengan kebutuhannya (mis. potret).
  3. Di Series Detail, klik satu foto → Lightbox terbuka, navigasi kiri/kanan untuk lihat lebih banyak dari seri yang sama.
  4. Menutup lightbox, klik nav About.
  5. Membaca bio singkat, scroll ke section Contact di halaman yang sama.
  6. Klik alamat email → membuka klien email lewat mailto:, atau klik tombol salin di sebelahnya untuk menyalin alamat langsung (dengan konfirmasi visual) — email adalah satu-satunya metode kontak (keputusan produk, PRD §10 Q04).

Flow B — Menjelajah cerita (Persona: Yoga)

  1. Membuka Discover langsung dari nav — tertarik format peta.
  2. Klik pin foto di peta → masuk ke Location Detail tempat itu.
  3. Menjelajah galeri, notice ada tautan “Bagian dari seri: ...” pada satu foto → klik → pindah ke Series Detail terkait.
  4. Dari Series Detail, klik tautan “Baca ceritanya” (kalau ada Blog Post terhubung) → ke Blog Post.
  5. Selesai baca, klik logo untuk kembali ke Home, lanjut menjelajah seri lain.

Flow C — JustLeps menambah karya baru (operasional, bukan UI publik)

  1. Menambah file foto ke folder aset, isi satu entri baru di content/photos.json (judul, caption, lokasi/seri).
  2. Menjalankan build lokal — skema tervalidasi otomatis, gagal cepat kalau ada field wajib kosong.
  3. Preview lokal untuk cek posisi foto di grid/seri yang relevan.
  4. git push — deploy otomatis ke GitHub Pages.
06

Layout per Screen

Home

Hierarki: Hero > Profil > Teaser konten. Satu primary action per section, tidak berebut.

Section (atas → bawah)
  1. Hero carousel bernotch (5 foto unggulan, autoplay 4.5s, dot manual)
  2. Kartu profil (avatar, nama, tagline, 2 social link, 1 CTA)
  3. “Latest Series” — grid 3–4 kartu, cover + nama
  4. “Latest Travel” — grid sama, cross-link ke Series terkait bila ada overlap foto
Primary action & komponen
Contact me → About
  • HeroCarousel, ProfileCard, SeriesCard/LocationCard grid
  • Semua kartu grid pakai komponen sama (lihat §7) — konsistensi wajib

Series Index & Travel Index

Struktur identik satu sama lain (Series = tematik, Travel = geografis) supaya pengunjung belajar polanya sekali.

Section
  1. Judul + 1 paragraf intro singkat
  2. Grid/List kartu (cover, nama, jumlah foto, negara untuk Travel)
Primary action & komponen
Klik kartu → Detail
  • SeriesCard / LocationRow
  • Tidak ada filter/search di MVP — volume foto masih kecil (lihat PRD Q06)

Series Detail & Location Detail

Layar “kerja” utama — tempat foto benar-benar dilihat.

Section
  1. Breadcrumb kembali + judul + metadata (negara/jumlah foto)
  2. Grid foto (PhotoCard), 3 kolom desktop
  3. Lightbox overlay saat foto diklik
Primary action & komponen
Klik foto → Lightbox
  • Gallery grid, PhotoCard, Lightbox (prev/next, caption, tautan silang seri↔lokasi)

Discover

Eksplorasi spasial — peta sebagai pengganti grid, bukan tambahan dekoratif.

Section
  1. Peta full-bleed di bawah nav (Leaflet + OSM)
  2. Pin foto per lokasi dengan badge jumlah
Primary action & komponen
Klik pin → Location Detail
  • MapPin (custom marker), zoom control bawaan Leaflet (di-restyle)

Blog Index & Blog Post

Kedalaman naratif — layout split supaya foto sampul tetap terlihat sambil membaca.

Section
  1. Media sticky kiri (cover foto)
  2. Kanan: intro + daftar post (badge New) / isi artikel
Primary action & komponen
Read → Blog Post
  • SplitLayout, BlogRow, Badge

About + Contact

Layar konversi — satu-satunya tujuan adalah membuat kontak semudah mungkin.

Section
  1. Media sticky kiri (portrait/behind-the-scenes)
  2. Kartu profil ringkas + kartu social link
  3. Paragraf About
  4. Section Contact: satu ContactMethodRow (email) + tombol salin — email satu-satunya metode kontak, tidak ada WhatsApp/form pihak ketiga (PRD §10 Q04)
Primary action & komponen
Klik/salin kontak
  • SplitLayout, ContactMethodRow, Toast (konfirmasi salin)

Component Library

Contoh render nyata untuk komponen berbasis teks/warna:

New 8 foto

  • Button / PillLink

    Variantsolid (CTA utama), outline (sekunder), ghost (tersier/navigasi kembali)
    Statedefault, hover (border/opacity naik), focus-visible (outline accent-text 2px), disabled (opacity 0.4, no pointer)

  • Badge

    Variantnew (post blog terbaru), count (jumlah foto per lokasi/pin peta)
    Statestatic — tidak interaktif, tidak punya state

  • PhotoCard

    Variantgrid (aspect-ratio 1:1, dipakai di semua galeri), featured (aspect 4:3, dipakai di hero carousel)
    Stateloading (skeleton shimmer), loaded, hover (overlay judul+lokasi muncul), error (fallback ikon foto pecah + label “Gambar tidak bisa dimuat”)

  • Lightbox

    Variantsingle (dipakai di semua galeri)
    Stateclosed (opacity 0, pointer-events none, tetap di DOM), open, image-loading (blur-up placeholder), first/last item (sembunyikan tombol prev/next yang tidak relevan)

  • SplitLayout

    Variantmedia-left (default, dipakai Travel/About/Blog)
    Statemedia-crossfade saat item aktif berganti (mis. hover baris lokasi)

  • SeriesCard / LocationRow

    Variantcard (grid, dipakai Home & index), row (list padat, dipakai Travel index)
    Statedefault, hover (border/media highlight)

  • MapPin

    Variantsingle-photo, cluster (badge angka saat >1 foto)
    Statedefault, hover (scale 1.05), selected (ring accent)

  • ContactMethodRow

    Variantlink (mailto: — langsung buka klien email), copy (tombol salin alamat ke clipboard, sebagai alternatif kalau klien email tidak terpasang)
    Statedefault, hover, copied (label berubah sementara ke “Tersalin” + ikon centang, 2 detik)

  • Toast / Snackbar (baru)

    Variantsuccess (salin berhasil), error (mis. clipboard API diblokir browser)
    Stateenter (slide+fade 200ms), visible (3s), exit

  • Skeleton (baru)

    Variantphoto (aspect-ratio placeholder), text-line
    Statepulsing animation, respects prefers-reduced-motion (jadi statis, bukan hilang)

  • EmptyState (baru)

    Variantno-photos (seri/lokasi kosong), no-results
    Stateselalu menyertakan 1 tautan keluar (mis. “Lihat semua Series”) — tidak pernah jalan buntu, selaras Prinsip 3

Kebutuhan ARIA
  • Lightbox: role="dialog" + aria-modal="true" + aria-label berisi judul foto aktif.
  • Nav aktif: aria-current="page" pada link rute yang sedang dibuka.
  • Toast: role="status" + aria-live="polite" supaya konfirmasi “Tersalin” terbaca screen reader tanpa memotong ucapan yang sedang berjalan.
  • Setiap foto: alt wajib diisi dari field title/caption pada data model — ditegakkan lewat validasi skema build (bukan konvensi lisan).
  • Landmark: <nav>, <main>, <footer> eksplisit di setiap screen (sudah demikian di kode saat ini — dipertahankan).
  • Peta: kontainer Leaflet diberi role="application" hanya jika interaksi drag esensial; kalau tidak, sediakan daftar teks lokasi sebagai alternatif non-visual (link tersembunyi ke Travel Index).
  • Toggle tema: role="switch" + aria-checked (sudah diimplementasi) — pertahankan.
